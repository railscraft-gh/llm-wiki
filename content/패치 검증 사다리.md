# 패치 검증 사다리

## 한 줄 정의
**패치 검증 사다리(Patch Verification Ladder)**는 [[LLM]] 보안 패치 에이전트가 제안한 소스코드 보정안이 결함을 올바르게 수정했는지 검증하기 위해 (T0) 컴파일/빌드, (T1) PoC 공격 방어, (T2) 정상 회귀 테스트, (Re-attack) 우회 공격 스웜 수비력 등 단계별 가로막 관문을 순차적으로 타고 올라가도록 설계된 실증적 실행 검증 워크플로우이다.

## 핵심 요지
- **단계별 가로막 관문 순차 검증**: 보정 코드는 단순 코드 스타일이나 모델의 구두 설명에 의해 평가되지 않고, 컴파일 성공(T0)부터 기존 공격 차단(T1), 정상 기능 보존(T2), 우회 변종 공격 수비(Re-attack)까지 단계별 오라클 관문을 모두 통과해야 최종 승인(ACCEPT)된다 (`raw/Building an Agentic Security Pipeline That Finds, Proves, and Patches Vulnerabilities.md`).
- **물리적 예외 트레이스 환류 및 자율 복구 (Self-Correction)**: 관문 통과 실패 시, 물리 오라클이 수집한 [[AddressSanitizer]](ASAN) 결함 로그나 빌드 에러를 패치 에이전트에 피드백으로 전달하여 최대 5회까지 자율적으로 수정본을 재작성하도록 유도한다 (`raw/Building an Agentic Security Pipeline That Finds, Proves, and Patches Vulnerabilities.md`).
- **최소 수정 원칙 (Minimal Patching)**: 취약점의 근본 원인(Root Cause)만 정밀하게 타격하고 무관한 소스코드는 손대지 않는 최소 수정을 강제함으로써, 예기치 않은 사이드 이펙트를 방지하고 보안 아키텍트의 코드 리뷰 용이성을 극대화한다 (`raw/Building an Agentic Security Pipeline That Finds, Proves, and Patches Vulnerabilities.md`).
- **독립적 메인테이너 사후 리뷰**: 물리적 실행 관문을 완벽히 통과한 검증본에 한해, 사전에 취약점 이력을 보지 않은 백지 상태의 독립 리뷰 에이전트가 패치 Diff를 심사하여 가독성 및 미적 정돈 점수(0~10점)를 매긴다 (`raw/Building an Agentic Security Pipeline That Finds, Proves, and Patches Vulnerabilities.md`).
