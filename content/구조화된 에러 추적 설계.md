# 구조화된 에러 추적 설계

## 한 줄 정의
구조화된 에러 추적 설계는 모호한 텍스트 에러 대신 시스템 식별용 [[구조화된 출력 및 도구 호출|에러 코드]]와 비즈니스 컨텍스트(요청 ID, 엔티티 ID, 실패 사유)를 결합하여, 디버깅 및 AI 에이전트 장애 분석의 효율성을 극대화하는 소프트웨어 설계 방식이다.

## 핵심 요지
- **기계와 인간 분리**: 모호한 단일 에러 메시지(`"Something went wrong"`) 대신, 시스템은 기계 식별용 코드(`code`), 사용자는 가독용 메시지(`message`), 로그는 명확한 맥락 객체(`details`, `requestId`)를 전달해야 한다 (raw/7 Coding Patterns I Stole From Senior Engineers.md).
- **문자열 구문 분석 방지**: 클라이언트나 프론트엔드가 에러 메시지 문자열(`error.message.includes("...")`)을 직접 파싱하는 취약한 구조를 차단하고 시스템 안전성을 확보한다 (raw/7 Coding Patterns I Stole From Senior Engineers.md).
- **보안 및 트레이싱 조화**: 흉측한 스택 트레이스나 비밀번호·인증 토큰 등 기밀 데이터를 외부로 노출하지 않으면서, 내부 로그에는 `requestId` 기반으로 역추적 가능한 식별자와 구조화된 사유를 남긴다 (raw/7 Coding Patterns I Stole From Senior Engineers.md).
- **LLM/에이전트와의 호환성**: [[AI 에이전트 제어 루프]] 또는 [[샌드박스 코드 실행]] 환경에서 LLM이 시스템 장애를 자동으로 파악하고 자가 수리(self-healing)를 수행하려면 고도로 규격화된 에러 응답 구조가 필수적이다.
