# 비동기 맥락 질문 및 /btw 명령어

## 한 줄 정의

AI 코딩 에이전트 작업 중 메인 작업의 [[컨텍스트 윈도우 한계 극복 요령|컨텍스트(Context)]]와 [[컨텍스트 스위칭]] 없이, 진행 중인 대화 흐름을 방해하지 않고 독립적인 보조 질문에 응답을 얻어내는 비동기 맥락 질의 워크플로우.

## 핵심 요지

* **몰입 흐름(Flow State) 보존**: 복잡한 아키텍처 작업이나 리팩터링 도중 떠오르는 개념적 질문(예: JWT 대 Session Cookie 비교)을 할 때, 메인 세션의 대화 맥락과 작업 단계를 오염시키지 않고 즉시 답변을 얻을 수 있다 (raw/Claude Code를 6개월 동안 잘못 썼다. 모든 걸 바꾼 14가지 명령어 - 출판형 다듬기.md).
* **인지 과부하 방지**: 뇌의 병렬 처리(Parallel Processing)처럼 주요 구현 줄기를 유지한 상태에서 부가적인 지식 탐색 실마리를 붙잡아 두는 인지 보조 도구 역할을 수행한다 (raw/Claude Code를 6개월 동안 잘못 썼다. 모든 걸 바꾼 14가지 명령어 - 출판형 다듬기.md).
* **[[Claude Code 세션 운영 명령어]]와의 시너지**: `/btw` 명령어를 3주 이상 활용할 경우, 개발자가 세션 전환이나 브라우저 검색 탭 이동 없이 에이전트 인터페이스 안에서 즉각적인 사고 전환을 경험하게 된다 (raw/Claude Code를 6개월 동안 잘못 썼다. 모든 걸 바꾼 14가지 명령어 - 출판형 다듬기.md).

## 상세

[[Claude Code 세션 운영 명령어|Claude Code]] 등과과 같은 CLI 기반 LLM 에이전트 세션에서 긴 작업(예: 147개 이상의 메시지가 누적된 대규모 디버깅 세션)을 진행할 때, 개발자는 다음과 같은 전형적인 세 가지 선택지 문제에 직면한다 (raw/Claude Code를 6개월 동안 잘못 썼다. 모든 걸 바꾼 14가지 명령어 - 출판형 다듬기.md):

1. **외부 검색 전환**: 에이전트를 벗어나 브라우저 검색을 수행하며 몰입 상태(Flow state)가 단절됨.
2. **메인 세션 질문**: 메인 대화 세션에 직접 질의하여 이전 디버깅/구현 맥락과 프롬프트 이력을 혼선시킴.
3. **질문 보류**: 궁금증을 메모만 해 두고 확인하지 않은 채 넘어가 기술 부채나 이해 부족을 초래함.

`/btw` 명령어(by the way)는 이 중 2번과 1번의 한계를 극복하는 비동기 사이드 채널(Side-channel) 질문 방식이다. `/btw` 뒤에 질의내용을 붙여 실행하면, LLM 에이전트(예: Claude 3.7 Sonnet 또는 Opus 모델)는 진행 중이던 핵심 코드 작성 스택이나 히스토리를 덮어쓰거나 오염시키지 않고 옆 질문에만 독립적으로 짧게 답변을 제공한다.

이 패턴은 [[컨텍스트 계층화|컨텍스트 엔지니어링(Context Engineering)]] 측면에서 메인 대화 스레드의 토큰 사용량을 아끼고, 대화 히스토리가 느려지는 현상을 완화하는 효과를 제공한다.

## 예시

### 활용 시나리오

개발자가 Claude Code 세션에서 Opus 모델을 활용하여 복잡한 인증/인가 미들웨어를 구축하던 중, Refresh Token 저장 방식에 대한 아이디어가 떠오른 상황:

```bash
# 메인 작업 세션 진행 중
> /btw refresh token은 어떻게 처리하는 게 제일 좋아?

# LLM 출력 (메인 프롬프트 맥락을 손상시키지 않고 질의 답변만 독립 표시)
💡 [BTW]: Refresh Token은 보안상 HttpOnly, Secure 플래그가 설정된 쿠키에 저장하거나, Redis 기반 전역 세션 저장소와 짧은 만료시간의 Access Token 조합을 사용하는 것이 표준적입니다.

# 이후 사용자는 기존 작업 흐름으로 바로 돌아와 코드 작성을 재개
> 계속해서 JWT 인증 미들웨어 생성을 진행해 줘.
```

## 충돌

* 현재 소스 문서 간 혹은 기존 이론 간 직접적인 충돌은 보고되지 않았다.
* **단, 주의점**: `/btw` 명령어로 제공받은 정보가 현재 프로젝트의 구체적 코드 파일 맥락(Context)을 완전히 공유하는지, 아니면 단일 보조 질의용 추론에 그치는지에 대한 디테일 차이가 있을 수 있으므로, 프로젝트 커스텀 컨텍스트가 깊게 개입되어야 하는 질문인 경우 차라리 메인 세션 질의나 `/compact` 후 질의가 유리할 수 있다는 점을 유의해야 한다.
