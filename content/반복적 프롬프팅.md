# 반복적 프롬프팅

## 한 줄 정의
**반복적 프롬프팅(Iterative Prompting)**은 대형 언어 모델([[LLM]])에 대한 프롬프트 입력을 일회성 지시(One-Shot)가 아닌 대화형 피드백 루프로 정의하고, 생성된 초안에 기반해 의도적인 수정 지시를 단계별로 가하며 아웃풋의 품질과 정확도를 정밀하게 높여가는 워크플로(Workflow) 기법이다.

## 핵심 요지
- **단발성 프롬프팅(One-Shot Prompting)의 한계 극복**: 난도가 높고 복잡한 실무 태스크는 단 한 번의 지시로 완벽한 결과를 얻기 어려우며, 단발성 프롬프트 실패 시 AI의 성능 한계로 치부하는 실수를 방지한다.
- **3단계 피드백 루프 구축**: 아웃풋과 목표 간의 차이(Gap) 규명 -> 4대 프롬프트 변수 중 단일 변수 튜닝(Variable Tuning) -> 구체적 구간 수정 명령(Refinement Command)의 3단계를 순환 적용한다.
- **의도적인 변수 통제**: 한 번에 하나의 프롬프트 변수(Persona, Task, Context, Format)만 손을 대어 피드백과 결과물 변화 사이의 인과관계를 정확히 통제한다.
- **50% 룰 기반의 세션 재시작 및 점진 개선 판단**: 초안 아웃풋의 50% 이상을 수정해야 할 만큼 조준점이 어긋난 경우 세션을 새로 열고, 아웃풋의 큰 골격이 양호하면 대화를 유지하며 점진적으로 개작한다.
- **Context Window 제약 대응**: 지속적인 반복 수정으로 인한 [[컨텍스트 세금]] 및 메모리 한계(Context Window 오염)를 방지하기 위해 핵심 규칙 반복 재선언, 맥락 자료 경량화, 마이크로 태스크(Micro Task) 분할 기법을 병행한다.

## 상세
- **3단계 피드백 루프**: 차이(Gap) 규명, 단일 변수 튜닝(Persona/Task/Context/Format 중 1개), 구체적 구간 수정 명령
- **50% 룰 기반 의사결정**: 50% 이상 수정 필요 시 세션 리셋 vs 50% 미만 수정 시 세션 유지 점진 보완
- **Context Window 메모리 제약 관리**: 핵심 조항 재선언(Rule Reinforcement), 자료 경량화(Context Pruning), 모듈형 지시(Micro-tasking)

## 예시
- **B2B 콘텐츠 마케팅 글 피드백 루프 실무 시나리오**: ChatGPT (GPT-4o), Claude 3.5 Sonnet, Gemini 1.5 Pro 모델을 기준으로 1차 지시(초안) -> 2차 지시(톤앤매너/포맷 수정) -> 3차 지시(결론부 행동 유도 질문 마감) 단계별 프롬프트 코드 구성 예시 수록

## 충돌
- **단발성 완료 미학 vs 반복 수정의 인지적 비용**: 완벽히 설계된 zero-shot/few-shot 1회 프롬프트가 토큰/시간 절약의 최선이라는 주장에 대립하여, 복잡 실무에서는 2~3회 반복 피드백 루프 적용이 사후 10분의 고통스러운 수정 작업을 방지한다는 실무 가이드 주장 명시
