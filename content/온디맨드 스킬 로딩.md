# 온디맨드 스킬 로딩 (On-demand Skill Loading)

## 한 줄 정의
온디맨드 스킬 로딩은 AI 에이전트가 문제를 해결하는 과정에서 필요한 스킬(도구, 함수, 지시어 등)을 처음부터 컨텍스트 윈도우에 모두 채워 두지 않고, 추론 단계에서 특정 스킬이 필요해지는 시점에 동적으로 검출하여 컨텍스트에 주입(Injection)하는 아키텍처 워크플로우이다.

## 핵심 요지
- **토큰 경제성 및 리소스 최적화**: 모든 도구 스키마와 시스템 지시어를 프롬프트에 상시 적재하면 토큰 소모량이 극심해지며, 온디맨드 방식으로 필요한 것만 동적으로 로딩하여 컨텍스트 윈도우 공간을 아낀다.
- **추론 성능 및 품질 극대화**: 프롬프트의 지시어와 도구가 과도하게 많아지면 모델의 주의력 분산(Attention Dilution)과 "지침 무시" 현상이 일어나는데, 스킬 범위를 좁게 제한함으로써 수행 성공률을 향상시킨다.
- **확장 용이성**: 마스터 추론 루프의 수정 없이 독립적으로 작성된 스킬 파일(skills/)을 이름 기준으로 동적으로 가져다 쓸 수 있는 플러그인 형태로 시스템을 확장할 수 있게 한다.

## 상세
온디맨드 스킬 로딩은 Claude Code 및 대형 코딩 에이전트의 **컨텍스트 관리 계층(Context Management Layer)**에서 필수적인 핵심 컴포넌트이다.

### 1. 작동 워크플로우
1. **작업 수령 및 분석**: 마스터 루프가 사용자 목적을 읽고, 작업을 분류하여 도구 실행 전 훅(Pre-execution Hook)이나 인프라 에이전트를 통해 필요한 스킬 목록을 특정한다.
2. **동적 모듈 로딩**: 탐지된 스킬 파일(예: git/파일 조작 등)의 스키마와 프롬프트를 디스크 및 스킬 레지스트리(skills/)에서 동적으로 읽어온다.
3. **컨텍스트 주입**: 모델 호출 직전에 인풋 프롬프트에 조립하여 전달한다.
4. **스킬 릴리즈**: 작업 기억 장치(Working Memory)에서 해당 작업이 종결되면 로딩된 스킬을 컨텍스트 창에서 안전하게 탈락시켜 KV Cache를 초기화하고 공간을 회복한다.

### 2. 하네스 시스템 및 캐싱 최적화
이 방식은 하네스가 모델의 KV 캐시 최적화(KV Cache Optimization) 및 프롬프트 캐싱(Prompt Caching)과 맞물려 작동할 때 더욱 효과적이다. 고정적인 마스터 시스템 프롬프트 뒷부분에 필요한 스킬 블록만 조립함으로써 캐싱 적중률을 크게 해치지 않으면서 동적 기능 확장을 가능하게 한다.

## 예시
- **Claude Code의 파일 시스템 조작**: 에이전트가 검색이나 리팩터링 도중 특정 프로젝트 구조에서만 쓰이는 파일 파싱 함수나 Git Worktree 격리 도구가 필요해지는 경우, 평소에는 해당 도구의 스키마와 설명문을 로드하지 않고 있다가 해당 시점에 다이내믹하게 프롬프트 내에 바인딩하여 실행을 수행한다.

## 충돌
- **캐싱 미스(Caching Miss) 및 대기 오버헤드**: 스킬이 수시로 인제스트되고 제거되면 프롬프트 캐시 적중률이 낮아져, 매번 전체 프롬프트를 다시 계산하여 발생하는 네트워크 대기 오버헤드 및 API 비용 상승을 유발할 수 있다. 따라서 영속적으로 사용될 핵심 스킬 세트와 온디맨드 스킬 세트의 명확한 경계 설계가 요구된다.
