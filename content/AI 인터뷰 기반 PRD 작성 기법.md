# AI 인터뷰 기반 PRD 작성 기법

## 한 줄 정의
AI 인터뷰 기반 PRD 작성 기법(Interview-Driven PRD Generation)은 기획자나 개발자가 처음부터 백지 상태에서 [[PRD]](Product Requirement Document)를 직접 작성하는 대신, 대화형 LLM 에이전트가 역으로 아이디어와 기획에 대해 인터뷰 질문을 던지게 하고 그 답변을 바탕으로 논리적 공백을 보완하여 단일 진실 공급원(Single Source of Truth) 명세를 자동 생성하는 기획 기법이다.

## 핵심 요지
- **기획 작성 장벽 해소 ("게으른 방식")**: 빈 화면에서 구조화된 기획 문서를 처음부터 집필하는 부담을 줄이고, AI가 던지는 구체적인 질문에 순차적으로 대답함으로써 신속하게 명세의 골격을 갖춘다.
- **논리적 공백 및 무의식적 가정 검증**: AI가 질문을 생성하고 답변을 주고받는 과정에서, 기획자가 스스로 미처 고려하지 못했던 기획상의 빈틈, 예외 처리 케이스, 규칙의 모호함 등을 사전에 발견할 수 있다.
- **개발 매끄러움의 80% 결정**: 아이디어와 [[PRD]]를 사전에 세밀하게 다져 AI에게 풍부한 맥락(Context)을 제공하는 작업이 전체 제품 개발 과정의 매끄러움을 80% 이상 결정한다(raw/AI와 오픈소스로 300개 이상의 팟캐스트를 RPG 게임으로 만든 이야기 - LennyRPG 8시간 개발기.md).
- **에이전트 개발의 단일 진실 공급원(Single Source of Truth)**: 정교하게 완성된 PRD는 Claude Code, OpenAI Codex 등 향후 구현을 담당하는 AI 코드 에이전트들이 일관되게 참조할 명서적 기준점 역할을 수행한다.
- **다양한 입력 도구 연동**: visual canvas 도구(Miro Flows) 및 음성 입력 도구(Wispr Flow)를 결합하여 답변 속도와 맥락 전달력을 대폭 극대화할 수 있다.

## 상세

### 1. 3단계 파이프라인

1. **핵심 아이디어 및 시각화 준비 (Idea Definition & Visualization)**
   - 앱의 핵심 아이디어를 가치 제안 위주로 간결하게 정리한다.
   - UI/UX 인터랙션이 중요한 제품의 경우 포켓몬 스크린샷이나 Miro 보드 러프 스케치 등 시각적 자료를 함께 첨부하여 AI가 시각적/구조적 맥락을 쉽게 이해하도록 돕는다.

2. **AI 역인터뷰 진행 (AI-Led Interview)**
   - 기획자가 직접 PRD를 작성하는 대신, AI에게 아이디어와 시각 자료를 전달한 뒤 "이 제품을 실제 완성된 명세서로 만들기 위해 필요한 질문들을 던져달라"고 지시한다.
   - AI는 핵심 루프, 진행 보상, 단계별 예외 처리, 비즈니스 로직 제약 조건 등에 관한 직관적 질문 리스트를 생성한다.
   - 기획자는 텍스트 작성뿐만 아니라 음성 입력 도구(Wispr Flow 등)를 활용해 대답을 빠르게 정리할 수 있다.

3. **PRD 자동 생성 및 검증 (PRD Consolidation)**
   - 질의응답을 거쳐 확보된 답변 텍스트와 초기 리소스를 종합하여 AI가 종합 [[PRD]]를 작성한다.
   - 이 결과물은 전체 프로젝트 진행 중 AI 에이전트들이 공통으로 다루는 단일 진실 공급원(Single Source of Truth) 문서가 된다.

### 2. 생산성 증폭 툴 콤보

- **Miro Flows**: 아이디어 조각, 포켓몬풍 레이아웃 스크린샷, AI 인터뷰 질문 카드, 답변 메모를 visual canvas 위에서 화살표로 이어 완성도 높은 명세서로 엮어내는 비주얼 기획 보드 (raw/AI와 오픈소스로 300개 이상의 팟캐스트를 RPG 게임으로 만든 이야기 - LennyRPG 8시간 개발기.md).
- **Wispr Flow**: 키보드 입력 대신 음성으로 빠르게 답변을 쏟아낼 수 있게 해주는 음성 입력 툴 (raw/AI와 오픈소스로 300개 이상의 팟캐스트를 RPG 게임으로 만든 이야기 - LennyRPG 8시간 개발기.md).
- **Claude Code & Codex**: 완성된 PRD를 단일 진실 공급원으로 수용하여 아키텍처 수립 및 단위 코딩을 자율 수행하는 AI 에이전트 파이프라인.

## 예시

### 1. 실사례: LennyRPG 개발 시 적용 사례
- 레니 라치츠키(Lenny Rachitsky)가 공개한 300회 이상의 팟캐스트 에피소드 녹취록(raw/AI와 오픈소스로 300개 이상의 팟캐스트를 RPG 게임으로 만든 이야기 - LennyRPG 8시간 개발기.md) 데이터를 활용해 8시간 만에 픽셀 RPG 게임 'LennyRPG'를 만들 때 이 기법이 적용되었다.
- 포켓몬 스타일 퀴즈 배틀 스케치와 팟캐스트 데이터를 Miro 보드에 배치한 후 Miro Flows를 가동해 AI가 퀴즈 범위 설정, 구역 해금 조건, 진행 보상 등에 관한 질문 카드를 생성하게 했다 (raw/AI와 오픈소스로 300개 이상의 팟캐스트를 RPG 게임으로 만든 이야기 - LennyRPG 8시간 개발기.md).
- 질문 카드 뒤에 간결한 답변을 적는 방식으로 아이디어의 논리적 빈틈을 점검하였고, 302개 에피소드에 대응하는 퀴즈 파이프라인 명세를 완성했다 (raw/AI와 오픈소스로 300개 이상의 팟캐스트를 RPG 게임으로 만든 이야기 - LennyRPG 8시간 개발기.md).

### 2. AI 인터뷰어 프롬프트 템플릿 예시

```markdown
# Role Definition
당신은 완벽한 제품 명세서([[PRD]])를 구성하는 리드 프로덕트 매니저(PM)입니다.

# User Input
- 아이디어 요약: 300개의 팟캐스트 게스트와 퀴즈 대결을 펼치는 포켓몬 풍 픽셀 RPG 웹 게임
- 핵심 화면: 2D 타일 맵, 퀴즈 배틀 박스, 도감 및 리더보드 UI 스케치

# Instruction
제시된 아이디어를 바탕으로 실제 개발 에이전트(Claude Code 등)가 오차 없이 구현할 수 있는 PRD를 작성하고자 합니다. 
PRD를 작성하기 전에, 기획의 논리적 공백과 제약 조건을 명확히 하기 위한 5가지 핵심 기획 질문을 나에게 던져주세요.

[질문 영역]
1. 퀴즈 진행 및 실패/성공 조건 (XP, HP 시스템 등)
2. 구역(Stage) 해금 및 맵 진행 방식
3. 게스트 아바타 및 녹취록 데이터 처리 방식
4. 백엔드/리더보드 동기화 요구사항
5. 예외 상황 처리
```
