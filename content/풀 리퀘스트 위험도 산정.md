### 2. '풀 리퀘스트 위험도 산정' 워크플로우 요약
* **개념 정의**: PR을 제출하기 전, 정적 분석(AST 및 의존성 그래프)을 기반으로 수정한 소스 코드의 전역 호출 빈도, 보안 키워드, 테스트 보장 여부 등 다각적인 잠재 리스크를 계량화하여 게이팅(Merge Gate)을 제어하는 개발자 안전 워크플로우입니다.
* **가중치 기반 점수 산정**:
  * **전역 호출 빈도** (가장 큰 가중치 부여, 결함 파급력과 연계)
  * **단위 테스트 보장 유무** (누락된 테스트 케이스 수록 여부)
  * **보안 예약 키워드** (Auth, Credentials, SSL 등)
  * 기타 순환 복잡도 증가량, 간접 의존 경로 등을 상한선(limit) 범위 내에서 합산 계산합니다.
* **실무적 한계 및 충돌 제어**:
  * **정적 오분석률**: 의존성 판정 중 40% 정도의 허위 탐지(False Positive) 가능성을 내포하고 있으므로 (`raw/Andrej Karpathy’s Fix for LLM Memory Works on Code Too.md`), 이를 1차 검증용 힌트로 삼고 개발자의 교차 분석이 결합되어야 합니다.
  * **동기화 지연**: 편집 도중 인덱스 해시가 어긋날 위험에 대비하여, 최종 게이팅 전에는 수동으로 그래프 인덱스를 완전 갱신(`code-review-graph build`)하는 패턴을 권장합니다.
