# 프로그래머블 지식 관리 시스템

## 한 줄 정의
**프로그래머블 지식 관리 시스템(Programmable Knowledge Management System)**은 단순한 텍스트 저장·연결을 넘어 [[LLM]] Agent 및 커스텀 스크립트/명령어를 통해 지식 데이터베이스(Vault)를 자동화·분석·재구성하는 능동형 세컨드 브레인 구축 파라다임이다.

## 핵심 요지
- **패시브 수집에서 액티브 워크플로로 전환**: 기존의 [[PKM]](Personal Knowledge Management) 및 [[PARA 방법론]]이 노트 정리 및 저장(Passive Storage)에 의존했다면, 프로그래머블 PKM은 지식을 스스로 동기화, 요약, 추출, 검증하도록 자동화(Active Automation)한다.
- **Local-First Plain Text 기반**: 파일 시스템 기반의 마크다운(.md) 지식 베이스(예: [[Obsidian]])를 LLM/CLI 도구(예: Anthropic의 Claude Code)의 작업 디렉터리로 직접 연결하여 데이터 주권과 자연어 프로그래밍 가능성을 동시에 확보한다.
- **자연어 인터페이스 제어**: 복잡한 코드 작성 없이 `CLAUDE.md`와 같은 시스템 운영 매뉴얼과 마크다운 기반 Slash Command 프롬프트를 작성하여 지식 관리 로직을 구축한다.

## 상세

### 1. 프로그래머블 지식 관리의 4대 메커니즘
프로그래머블 지식 관리 시스템은 전통적인 [[세컨드 브레인]] 관리의 비효율성을 메우기 위해 다음과 같은 커스텀 자동화 루틴(Slash Commands)을 활용한다.

1. **컨텍스트 자동 동기화 (`/sync`)**:
   - 세션 시작 시 지난 주간 노트, 활성 프로젝트, 태스크 목록, Inbox 항목, 최근 7일 수정 노트를 스캔하여 현재 시점의 우선순위 신호(focus, urgent, important)를 구조화된 요약 형태로 자동 로드한다.
2. **사고 진화 타임라인 추적 (`/trace`)**:
   - Vault 내 `[[wikilinks]]`와 파일 수정 이력을 스캔하여 특정 개념이 처음 등장한 시점부터 현재 연결망으로 발전하기까지의 시간 흐름을 시각화한다.
3. **지식 그래프 점검 및 브리지 탐색 (`/connect`)**:
   - Direct, 1-hop, 2-hop 연결 경로를 추적하여 고립된 노트(Orphan Notes) 및 서로 다른 개념 간의 Bridge Note를 식별해 지식의 고립화를 막는다.
4. **자동화된 파이프라인 승격 및 분류 (`/graduate`, `/inbox`)**:
   - 주간 노트(Weekly Notes)나 파편화된 메모에서 미완성 아이디어("I think...", "What if...")를 추출하여 씨앗 노트(Seedling)로 자동 승격시킨 뒤, [[PARA 방법론]] 원칙(Projects, Areas, Resources, Archive)에 따라 적절한 폴더로 분배한다.

### 2. 가상 데블스 어드보킷(Devil's Advocate) 및 패턴 채굴
- **신념 압박 테스트 (`/challenge`)**: 작성자의 노트들에 축적된 주장 간 모속, 암묵적 숨은 가정, 논리적 약점을 정면으로 검증하여 비판적 사고를 보조한다.
- **패턴 기반 아이디어 추출 (`/ideas`)**: 단순 무작위 아이디어 제안이 아닌, 지난 30일간의 vault 활동 이력과 답답함/미해결 질문 패턴을 분석해 실제 작성자의 맥락에 결합된 연구·개발 주제를 도출한다.

## 예시

### 1. `CLAUDE.md` 운영 매뉴얼 예시
Obsidian Vault 루트 디렉터리에 `CLAUDE.md`를 배치하여 LLM에게 폴더 구조, [[Obsidian]] 문법, 지식 관리 규칙을 가르친다.

```markdown
# CLAUDE.md

## Overview
This is an Obsidian vault organized using the PARA method (Projects, Areas, Resources, Archive).

## Folder Structure
- `0. Inbox/` - 정리되지 않은 메모 및 유입 콘텐츠
- `1. Projects/` - 마감이 있는 활성 프로젝트
- `2. Areas/` - 지속 책임 영역
- `3. Resources/` - 참고 자료 및 관심 주제
- `4. Archive/` - 완료/비활성 항목
- `_Weekly/` - YYYY-WXX 형태의 주간 노트

## Obsidian-Specific Syntax
- Tasks query: `tasks \n not done \n path includes 1. Projects/`
- Internal link: Standard Obsidian `[[wikilinks]]`
```

### 2. Slash Command 정의 파일 (`.claude/commands/graduate.md`)
주간 노트에서 새로운 아이디어를 추출해 독립 마크다운 파일로 승격시키는 프로그래머블 지시문 프롬프트 구조 예시:

```markdown
---
description: Extract floating ideas from weekly notes into seedling notes
---
1. Scan files in `_Weekly/` modified in the last 4 weeks.
2. Find standalone observations, unaddressed questions, or sentences starting with "I think..." or "What if...".
3. Create a new note in `0. Inbox/Graduates/` using the format:
   # [Core Claim in One Line]
   **Graduated from**: [[Weekly Note Link]]
   **Status**: Seedling
   ## Core Claim
   ## Context
   ## Original Excerpt
   ## Connections
```

### 3. 실제 시스템 구현 시나리오 (Anthropic Claude Code 기반)
- **엔진**: Anthropic Claude Code CLI 도구 (또는 동급의 파일 시스템 접근 능력을 보유한 [[LLM Agent]])
- **환경 구성**: Obsidian Vault 최상위 폴더에 `.claude/commands/` 구조를 배치하고 `trace.md`, `sync.md`, `connect.md`, `inbox.md`, `graduate.md`, `ghost.md`, `challenge.md`, `ideas.md` 8개 커스텀 명령어를 정의하여 운영한다 (`raw/Claude Code + Obsidian으로 AI 기반 세컨드 브레인을 만든 방법 - 출판형 다듬기.md`).
