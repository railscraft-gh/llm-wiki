# 빌드가 싸지면 논쟁이 비싸진다

## 한 줄 정의
AI 기반 자동화 및 소프트웨어 개발 도구(예: Claude Code)로 인해 코딩 및 프런트엔드/백엔드 프로토타이핑 비용(빌드 비용)이 극도로 낮아진 반면, 사전 디자인 문서 작성이나 화이트보드 미팅 등 구두·서면 기반 기술 논쟁의 상대적 기회비용은 비싸졌음을 나타내는 인사이트이다.

## 핵심 요지
- **엔지니어링 병목의 이동**: 기존 개발 프로세스는 '엔지니어링 대역폭(코딩 처리량)'이 가장 비싼 자원이라는 전제하에 설계되었으나, AI 도구의 도입으로 구현(Building) 비용이 사실상 0에 가깝게 감소했다.
- **Code Wins 중심 문화**: 거창한 사전 디자인 문서 작성이나 긴 미팅보다, Claude 등 AI를 활용해 여러 사양의 실제 프로토타입(PR)을 동시다발적으로 생성하고 직접 비교·테스트하는 것이 훨씬 효율적이다.
- **새로운 병목의 출현**: 빌드가 저렴해짐에 따라 소프트웨어 조직의 진짜 병목은 코딩이 아니라 **검증(Verification)**, **코드 리뷰(Review)**, **유지보수(Maintenance)**, **보안(Security)**, 그리고 **교차 기능 파트너 간 역할 정렬**로 이동했다.

## 상세
과거 개발 조직은 구현(Building)에 소요되는 엔지니어링 리소스가 비쌌기 때문에, 구현 전 실패 위험을 줄이기 위해 장기의 6개월 로드맵, 사전 디자인 문서, 50인 주간 리뷰 미팅 등의 사전 검증 프로세스를 겹겹이 두었다.

그러나 Anthropic Claude Code 팀의 엔지니어링/제품 총괄 Fiona Fung의 2025년 5월 22일 Anthropic 첫 개발자 컨퍼런스 발표(Code w/ Claude 세션)에 따르면, 개발 현장에서는 이 같은 전제가 더 이상 유효하지 않다 (`raw/AI 네이티브 엔지니어링 조직 운영하기 - Code w Claude 발표.md`).

- **Claudify Everything 및 JIT Planning**: 사전 문서 작성이나 화이트보드 논의 대신 필요한 시점에 적절한 양만 기획하는 JIT(Just-In-Time) Planning을 적용하고, 아이디어가 생기면 PR 자체를 논의의 장으로 활용한다 (`raw/AI 네이티브 엔지니어링 조직 운영하기 - Code w Claude 발표.md`).
- **신뢰하되 검증하라 (Trust but Verify)**: 단순 코드 작성 및 린트, 기본 버그 케치, 테스트 코드는 AI에게 넘기고, 인간 엔지니어는 시스템 전문성, 보안 신뢰 경계, 제품 감각(Product Sense) 및 취향(Taste) 검증에 집중한다 (`raw/AI 네이티브 엔지니어링 조직 운영하기 - Code w Claude 발표.md`).
- **실증 데이터 지표**: 발표팀 조사 결과, Claude-assisted 커밋 비율은 지난 4개월간 거의 100%에 달했으며, 온보딩 램프업 시간 및 PR 사이클 타임이 단축되는 성과를 나타냈다 (`raw/AI 네이티브 엔지니어링 조직 운영하기 - Code w Claude 발표.md`).

## 예시

### 시나리오: API 리팩토링 기술 논쟁
과거 API 디자인 리팩토링 시 개발자 Boris와 Fiona가 화이트보드 앞에서 몇 시간 동안 구조 설계를 논쟁했다면, 현재는 Claude Code를 사용하여 3개의 서로 다른 API 디자인 구현안을 다중 PR 형태로 몇 분 만에 자동 생성한다.

```bash
# Claude Code CLI를 활용하여 서로 다른 3가지 API 리팩토링 프로토타입 PR을 자동 생성
claude "Refactor user authentication service using Option A (JWT Bearer Token pattern) and open PR"
claude "Refactor user authentication service using Option B (OAuth2 Introspection pattern) and open PR"
claude "Refactor user authentication service using Option C (Session Cookie pattern) and open PR"
```

위와 같이 실제 코드를 생성하여 호출자(caller)에 미치는 파급력 및 테스트 커버리지를 즉시 눈으로 확인한 뒤 최적안을 채택함으로써, 불필요한 서면/구두 논쟁 비용을 없애고 [[Code Wins 문화]]를 실천한다.
