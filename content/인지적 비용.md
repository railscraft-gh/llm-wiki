# 인지적 비용

## 한 줄 정의
인지적 비용(Cognitive Expense/Load)은 인간이 정보를 처리하고, 의사결정을 내리며, 복잡한 시스템이나 타인의 작업 결과물(특히 AI 에이전트가 생성한 코드)을 검증하고 디버깅하는 과정에서 소모하는 정신적 에너지와 뇌의 연산 부하를 의미한다.

## 핵심 요지
- **생산성 지표의 이면**: AI [[코딩 에이전트]] 도입으로 인해 코드 생성(Generation) 속도는 기하급수적으로 빨라지고 전체 개발 주기 대시보드상 처리량(Throughput) 지표는 향상되지만, 정작 코드를 검증하고 디버깅하는 하류(Downstream)의 [[코드 리뷰 대기열 병목]]과 인지적 하중은 급격히 증가한다.
- **창작과 검증의 비대칭성**: 스스로 설계를 고민하고 구현하는 코딩은 깊은 성취감과 창작의 희열을 주지만, AI가 "지나친 자신감"으로 쏟아낸 코드를 읽고 미세한 결함을 잡아내는 검증 작업은 성취감이 결여된 채 극도의 정신적 피로를 유발한다.
- **수치적 현실**: AI 코딩 도구 도입 이후 코드 리뷰 소요 시간은 **200% 증가**했으며, 엔지니어링 리더의 **86%**는 시니어 엔지니어가 버그를 수정하는 일에 이전보다 훨씬 많은 시간을 쓰고 있다고 답했다 `(raw/My Best Senior Engineer Quit Last Month. Her Exit Interview Was Scheduled for Forty Minutes. The Last Five Changed How I Run My Team..md)`.
- **조직적 대응 필요성**: 리뷰는 자연스레 해결되는 공짜 작업이 아니라 가장 막대한 인지적 비용이 드는 고강도 노동이다. 이를 방치하면 핵심 시니어 엔지니어의 번아웃과 이탈을 초래하므로, 리뷰 하중의 지표화 및 분산, [[PR 크기 및 수량 제어]], 창의적 설계 업무의 재할당 등이 필수적이다.

## 상세
AI 코딩 도구가 널리 보급되면서 소프트웨어 개발 생태계는 '코드 작성 중심'에서 '코드 검증 및 리뷰 중심'으로 패러다임이 시프트하고 있다. 이 과정에서 엔지니어가 겪는 인지적 비용의 성격이 근본적으로 변했다.

### 1. [[검증 레이어]](Verification Layer)로의 직무 변질
엔지니어가 복잡한 아키텍처를 주도적으로 설계하고 구현하는 일은 인간의 창의성을 발휘하는 과정이며, 지적 성취와 만족감을 제공한다. 그러나 AI 에이전트가 다량의 코드를 쏟아내기 시작하면 시니어 엔지니어는 자신이 작성하지 않은 코드를 검토하고 숨겨진 결함을 찾아내는 단순 '[[검증 레이어]]'로 전락하게 된다. 
이 일은 스스로 설계한 것이 아니기 때문에 코드의 맥락을 머릿속으로 다시 추적(Reverse-engineering)해야 하므로 훨씬 큰 뇌의 연산 부하가 필요하다. 만약 버그를 놓쳐 시스템 장애가 발생할 경우 그 최종 책임은 코드를 생성한 에이전트가 아닌 인간 검증자에게 귀착되므로 심리적 긴장감과 부담감도 함께 배가된다.

### 2. 인지적 지표의 감추어진 붕괴
기존의 개발 생산성 측정 도구(예: Velocity, PR merge cycle, Throughput 등)는 엔지니어가 겪는 내면의 인지적 고갈을 측정하지 못한다. 대시보드 지표가 최상의 상태를 가리키는 동안에도, 특정 시니어 엔지니어는 피로를 모르는 기계가 쏟아내는 리뷰 큐 끝에 서서 홀로 하중을 견디다가 번아웃에 직면하게 된다. 결국 이는 사직서라는 돌이킬 수 없는 형태로 가시화되며, 조직은 대체 불가능한 도메인 지식과 직관을 잃는 막대한 비용(시니어 1인 퇴사 시 약 15만~30만 달러 상당)을 치르게 된다 `(raw/My Best Senior Engineer Quit Last Month. Her Exit Interview Was Scheduled for Forty Minutes. The Last Five Changed How I Run My Team..md)`.

## 예시
### AI 에이전트 생성 코드의 교묘한 오류와 인지적 비용 발생 사례
다음은 `Gemini 1.5 Pro` 혹은 `Claude 3.5 Sonnet` 기반의 [[코딩 에이전트]]가 작성한 전자상거래 시스템의 결제 처리 API 코드의 예시다. 겉보기에는 에러 처리와 로그가 정갈하게 들어가 있어 쉽게 승인(Approve)하기 쉬우나, 분산 환경에서의 미세하고 치명적인 버그가 숨어 있어 리뷰어에게 심각한 인지적 추론을 요구한다.

#### AI가 작성한 결제 승인 코드
```typescript
// PaymentService.ts (AI Agent Generated)
import { Database } from './db';
import { PaymentGateway } from './gateway';

export class PaymentService {
  private db: Database;
  private gateway: PaymentGateway;

  constructor(db: Database, gateway: PaymentGateway) {
    this.db = db;
    this.gateway = gateway;
  }

  /**
   * 사용자의 결제 요청을 처리합니다.
   * @param userId 사용자 ID
   * @param orderId 주문 ID
   * @param amount 결제 금액
   */
  async processPayment(userId: string, orderId: string, amount: number): Promise<boolean> {
    // 1. 주문 상태 확인
    const order = await this.db.getOrder(orderId);
    if (!order || order.status !== 'PENDING') {
      throw new Error('Invalid order status');
    }

    // 2. 외부 결제 게이트웨이 호출 (API Call)
    const gatewayResult = await this.gateway.charge(userId, amount);
    if (!gatewayResult.success) {
      await this.db.updateOrderStatus(orderId, 'FAILED');
      return false;
    }

    // 3. 데이터베이스 상태 업데이트
    try {
      await this.db.updateOrderStatus(orderId, 'PAID');
      await this.db.saveTransaction(orderId, gatewayResult.transactionId);
      return true;
    } catch (dbError) {
      // ⚠️ 치명적인 동시성/멱등성 버그 지점
      console.error('Failed to update DB after successful gateway charge', dbError);
      return false;
    }
  }
}
```

#### 시니어 엔지니어가 이 코드를 검증할 때 마주하는 인지적 비용
1. **분산 상태 불일치 감지**: 게이트웨이 승인(`gateway.charge`)은 성공했으나, DB 업데이트(`updateOrderStatus`, `saveTransaction`) 단계에서 네트워크 이슈나 DB 락으로 예외가 발생할 경우, 결제 대금은 빠져나갔으나 주문 상태는 여전히 `PENDING` 혹은 업데이트되지 않은 상태로 남게 된다.
2. **멱등성(Idempotency) 부재 추적**: 사용자가 실패 응답을 받고 다시 결제를 시도하거나 재시도(Retry) 메커니즘이 동작할 때, 동일한 `orderId`에 대해 중복 결제가 발생할 위험이 존재한다.
3. **해결책 설계 하중**: 이 결함을 해결하기 위해 아웃박스 패턴(Outbox Pattern)이나 이중 쓰기 방지를 위한 분산 락, 혹은 외부 게이트웨이 호출 전 결제 시도 상태(`PROCESSING`)를 DB에 기록하고 고유 키를 통한 게이트웨이 멱등 키 제공 설계로 변경해야 한다. 

직접 코드를 짤 때는 자연스럽게 이러한 흐름을 설계에 반영하지만, AI가 즉각적으로 뱉어낸 '겉보기엔 완벽한' 코드 블록을 훑어보면서 그 이면에 숨겨진 동시성 부작용을 찾아내는 일은 고도의 집중력과 시스템 메모리를 요구하는 막대한 인지적 비용을 소모한다.
