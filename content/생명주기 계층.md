# 생명주기 계층

## 한 줄 정의
**생명주기 계층(Lifecycle Layer)**은 [[하네스 스택 모델]]의 5계층 중 최상위 신경계 역할을 담당하며, [[LLM]] 에이전트를 하나의 장기 실행 프로세스(Running Process)로 관리하여 시작·헬스 체크·우아한 종료·크래시 복구·비용 추적 및 인간 승인 게이트를 제어하는 인프라 레이어이다.

## 핵심 요지
- **핵심 질문**: "에이전트가 현재 정상 작동 중이며 목표를 향해 나아가고 있는가? 할당된 예산 내에서 돌고 있는가?"
- **주요 책임**: 프로세스 생명주기 관리, 헬스 체크, 무한 루프 감지 및 차단, 상태 동기화 및 크래시 복구(Checkpoint Recovery), 토큰 및 비용 예산 추적, 고위험 작업 시 인간 승인 게이트(Human Approval Gate) 관리.
- **변화 속도**: 느림. 인프라 성격으로 구축된 후에는 변경 빈도가 낮다.
- **담당 주체**: 프로덕션의 운영 신뢰성과 가시성(Observability)을 총괄하는 SRE(Site Reliability Engineering) 및 DevOps 팀.
- **플랫폼 책임 영역**: Anthropic의 Claude Managed Agents 등 관리형 에이전트 플랫폼에서 2계층([[컨텍스트 계층]]), 3계층(실행 계층)과 함께 플랫폼(벤더)이 가상화하여 기본 기능(Primitive)으로 제공하는 인프라 계층이다 (`raw/Anthropic Just Shipped Three of the Five Harness Layers for Managed Agent, and The Other Two Are on You.md`).

## 상세

### 1. 역할 및 필요성
에이전트가 장시간 자율적으로 동작할 때 생명주기 계층이 비어 있으면 감시받지 않는 고비용 위험 요인이 된다. 대표적인 시스템 실패 양상과 이 계층의 대응 역할은 다음과 같다:
- **비용 폭탄 및 무한 루프 방지**: 에러 상황에서 동일한 오작동을 되풀이하여 하룻밤 사이에 수천 달러의 API 비용이 소모되는 현상을 차단한다.
- **컨텍스트 손상(Context Rot) 예방**: 세션이 길어지면서 히스토리가 과도하게 누적되어 에이전트가 최초 목표를 망각하는 문제를 해결하기 위해 정기적으로 컨텍스트를 재구성하거나 세션을 갱신한다.
- **크래시 복구 및 세션 지속성**: 하네스나 컨테이너 인프라 다운 시 작업 이벤트 로그를 보존하고 `wake(sessionId)` 명령 등을 통해 직전 체크포인트 상태부터 이어받아 복구한다.
- **인간 개입 제어(Human-in-the-Loop)**: 데이터 삭제, 인프라 변경, 외부 메시지 전송 등 고위험 작업 시 승인 게이트를 거치도록 통제한다.

### 2. 주요 패턴 및 기술적 명세
- **루프 감지 미들웨어(Loop Detection Middleware)**: LangChain의 `LoopDetectionMiddleware`와 같이 파일당 편집 횟수나 도구 호출 패턴을 감지하여 반복 한도 초과 시 프롬프트 개입이나 자동 중단을 수행한다.
- **이중 에이전트 패턴(Dual-Agent Pattern)**: Anthropic의 패턴처럼 초기화 에이전트와 코딩 에이전트를 분리해 새 세션이 열릴 때 이전 전체 히스토리를 재주입하는 대신 최신 컨텍스트만 재구성하여 컨텍스트 손상을 원천 차단한다.
- **뇌-손 분리 및 세션 가상화 아키텍처**: 2026년 4월 Anthropic의 Claude Managed Agents는 에이전트 제어 루프(뇌), 샌드박스 실행 환경(손), 이벤트 기록 세션(로그)을 완전 디커플링하였다. 이를 통해 샌드박스 컨테이너 영속성에 의존하지 않는 구조를 달성했으며, 첫 토큰 발생 지연 시간 중간값(p50)은 60%, 95% 분위수(p95)는 90% 이상 단축되었다 (`raw/Anthropic Just Shipped Three of the Five Harness Layers for Managed Agent, and The Other Two Are on You.md`).

## 예시

### 1. 활용 시나리오
Claude Managed Agents 기반 환경에서 장시간 코딩 태스크를 수행하는 에이전트가 반복 에러 루프에 빠지거나 컨테이너 인프라가 다운되었을 때, 5계층 미들웨어가 루프 감지 신호를 포착해 우아하게 종료하거나 `wake(sessionId)` 호출로 상태를 핫 복구하는 시나리오.

### 2. 구체적인 코드 예시 (Python 기반 생명주기 제어 및 루프 감지 미들웨어 스니펫)

```python
import time
from typing import Dict, Any

class LifecycleManager:
    """에이전트 생명주기 계층 (5계층) 관리자"""
    def __init__(self, max_cost_usd: float = 10.0, max_file_edits: int = 5):
        self.max_cost_usd = max_cost_usd
        self.max_file_edits = max_file_edits
        self.file_edit_counts: Dict[str, int] = {}
        self.accumulated_cost: float = 0.0

    def track_cost(self, token_cost: float):
        self.accumulated_cost += token_cost
        if self.accumulated_cost > self.max_cost_usd:
            raise RuntimeWarning(
                f"[Lifecycle Layer] 예산 한도 초과 (${self.accumulated_cost:.2f} > ${self.max_cost_usd:.2f}). 에이전트를 종료합니다."
            )

    def check_loop(self, file_path: str) -> bool:
        """LangChain 루프 감지 미들웨어 스타일 패턴"""
        count = self.file_edit_counts.get(file_path, 0) + 1
        self.file_edit_counts[file_path] = count
        
        if count > self.max_file_edits:
            print(f"[Lifecycle Warning] {file_path} 파일이 {count}회 이상 연속 수정됨. 무한 루프 가능성 차단.")
            return False  # 에이전트에 개입 프롬프트 전달 또는 강제 중단
        return True

    def wake(self, session_id: str, event_log: list):
        """Anthropic Claude Managed Agents 스타일 wake(sessionId) 복구 로직"""
        print(f"[Lifecycle Layer] wake('{session_id}') 실행: 직전 이벤트 로그 {len(event_log)}건 복원 완료.")
        # 직전 상태에서 하네스 제어 루프를 재구동
```

## 충돌
본 문서 소스 내에서 명시적인 다른 서술과의 충돌은 발견되지 않았다. 다만 하네스를 구성 요소의 단순 나열로 보던 기존 6대 구성 요소 접근법과 달리, 5계층 [[하네스 스택 모델]]에서는 생명주기 계층이 2계층(컨텍스트), 3계층(실행)과 함께 개발자가 직접 구현하기보다 관리형 인프라 플랫폼(Anthropic Managed Agents 등)에 위임하여 구현하기 적합한 '플랫폼 인프라 계층'으로 격상해 재정의되었다 (`raw/Anthropic Just Shipped Three of the Five Harness Layers for Managed Agent, and The Other Two Are on You.md`).
