# LLM 메모리 시스템 아키텍처

## 한 줄 정의
LLM 메모리 시스템 아키텍처는 LLM 에이전트가 단기 대화 맥락과 장기 지식을 효율적으로 보존하고 인출할 수 있도록 슬라이딩 윈도우, 자동 요약, 벡터 검색, 지식 그래프, 계층형 자체 관리 루프 등 서로 다른 저장 계층과 관리 도구를 설계 및 결합하는 기술적 뼈대다.

## 핵심 요지
- **메모리 자율성 (Agentic Memory)**: 에이전트 외부에서 개발자가 수동적으로 컨텍스트를 주입하는 설계(Passive Memory)에서, 에이전트 스스로 도구(update, insert, search)를 호출하여 자신의 기억을 관리하고 인출하는 하트비트 루프(Heartbeat Loop) 기반의 자율 메모리 시스템으로 진화한다.
- **메모리 계층 구조 (Memory Hierarchy)**: 하드웨어의 RAM과 하드디스크의 이원화 구조처럼, 매 대화 턴마다 즉각 상주하며 갱신되는 **핵심 메모리(Core Memory)**와 방대한 지식을 저장하고 필요할 때 시맨틱 검색으로 퍼 올리는 **보관용 장기 메모리(Archival Memory)**로 계층을 설계하여 컨텍스트 예산(Context Tax)을 관리한다.
- **구축 기법의 트레이드오프**: 단순 순환 버퍼(FIFO)부터 지식 그래프(관계 추론) 및 MemGPT식 계층 메모리에 이르기까지, 각 메커니즘은 컴퓨팅 비용, 설명 가능성, 추론 복잡도 측면에서 명확한 트레이드오프를 가진다.

## 상세

### 1. 에이전트 메모리 구축의 5대 메커니즘

#### ① 슬라이딩 윈도우 버퍼 (Sliding-Window Buffer)
- **개념**: 가장 단순한 선입선출(FIFO) 방식의 순환 버퍼다. 고정된 토큰 크기나 대화 턴 수 한도를 정해두고, 이를 초과한 과거 대화 기록은 자동으로 잘라내어 버린다.
- **특징**: 컨텍스트 창 소모와 토큰 비용을 안전하게 통제할 수 있어 단기 맥락 유지에는 적합하나, 잘려 나간 기억은 영구 소실되므로 장기 기억 형성이 불가능하다.

#### ② 자동 요약 버퍼 (Auto-Summarization Buffer)
- **개념**: 대화가 특정 임계치에 도달할 때마다 이전 대화 내용을 LLM을 사용하여 요약본으로 점진적 압축 및 갱신해 나가는 기법이다.
- **특징**: 높은 정보 압축률을 달성해 오랜 기간 대화를 이어갈 수 있지만, 요약이 누적될수록 구체적인 세부 사항(고유 번호, 상세 수치, 고유 식별자 등)이 요약 과정(lost in distillation)에서 유실될 위험이 높다.

#### ③ 벡터 메모리 (Vector Memory)
- **개념**: 대화 내용이나 단편 정보를 일정 청크 단위로 쪼개어 임베딩한 후, 벡터 데이터베이스에 저장한다. 사용자 질문이 들어오면 유사도 검색(Semantic Search)을 통해 관련 맥락을 인출한다.
- **특징**: 무제한에 가까운 대규모 장기 기억을 지원하며 연상 검색에 뛰어나지만, 서로 떨어져 있는 다단계 논리 조각들을 연쇄적으로 추적해야 하는 멀티홉(Multi-Hop) 관계 추론에는 사각지대가 존재한다.

#### ④ 지식 그래프 메모리 (Knowledge-Graph Memory)
- **개념**: 정보를 개체(Node)와 개체 간의 의미론적 관계(Edge)로 추출하여 트리플렛(Triplet, 예: `Alice -> sister_of -> Bob`) 형태로 데이터베이스에 적재하고 그래프 쿼리로 인출한다.
- **특징**: 사실 정보(Ground Truth)의 무결성이 높고 경로 추적을 통해 결정론적이고 설명 가능한 멀티홉 추론을 수행할 수 있습니다. 반면, 데이터가 정형화되어야 하고 비정형 대화에서 관계 지도를 동적으로 추출·유지하는 비용이 높다.

#### ⑤ 계층형 자체 관리 메모리 (Hierarchical Self-Managed Memory)
- **개념**: 에이전트에게 메모리 업데이트(`core_memory_update`), 아카이브 저장(`archival_memory_insert`), 아카이브 인출(`archival_memory_search`) 도구를 제공하여, 모델이 스스로의 판단 하에 기억을 조작하고 제어 루프(Heartbeat Loop)를 통해 최종 응답 전까지 도구 호출을 반복 수행하게 만드는 구조다.
- **특징**: 정보의 능동적 기억, 수정, 장기 검색이 가능하여 가장 높은 수준의 자율성을 보장한다. 하지만 매 사용자 질문마다 발생하는 LLM 호출 횟수가 가변적이고 토큰 및 비용 오버헤드가 크므로 무한 루프 차단선(Safety Valve, 예: `max_llm_calls = 10`)이 필수적이다.

### 2. 메모리 아키텍처 성능 및 특성 비교표

| 메커니즘 | 컴퓨터 하드웨어 비유 | 장점 | 단점 | 적합한 사용 사례 |
| :--- | :--- | :--- | :--- | :--- |
| **슬라이딩 윈도우** | L1/L2 캐시 | 구현이 간단함, 예측 가능한 비용 | 장기 기억 소실 | 단발성 세션, 단순 Q&A |
| **자동 요약** | 가상 메모리 압축 | 적은 토큰으로 전체 흐름 유지 | 세부 지표 및 팩트 유실 | 장기 잡담, 비정형 회고록 |
| **벡터 메모리** | 하드디스크 (색인 검색) | 대규모 데이터 연상 검색 우수 | 멀티홉 관계 추론 취약 | 매뉴얼 검색, 장기 성향 기억 |
| **지식 그래프** | 구조화된 SQL DB | 높은 정밀도, 투명한 추론 경로 | 비정형 지식의 적재 비용 | 복잡한 관계망 추적, 보안 감사 |
| **계층형 자체 관리** | 운영체제(OS)의 가상 기억장치 관리 | 고도의 자율성, 능동적 정보 업데이트 | 가변적 호출 비용, 구현 복잡도 | 복잡한 자율 에이전트, 개인화 비서 |

## 예시
- **개인 맞춤형 피트니스 코칭 에이전트**: 사용자의 현재 신체 정보, 식단 알레르기, 오늘 운동 계획은 **핵심 메모리(Core Memory)** 딕셔너리에 상주시켜 프롬프트마다 띄워둔다. 반면 지난달의 인바디 기록과 과거 운동 일지 이력은 **보관용 메모리(Archival Memory)** 벡터 DB에 두고, 사용자가 "내 지난달 스쿼트 중량에 비해 이번 주 성장은 어때?"라고 물었을 때 에이전트가 `archival_memory_search` 도구를 호출해 관련 기록을 불러와 비교 분석한다.

## 충돌
- **메모리 팩트 무결성**: 에이전트가 사용자의 사실 정보를 기록할 때, 모순되거나 잘못된 정보를 제공받더라도 임의로 검열하거나 차단하지 않는 것이 원칙이다. 에이전트는 팩트 체커가 아닌 기록자(Archivist)로 동작해야 하기 때문이다. 다만, 보안 인증 정보 노출 등 치명적인 정보의 오염에 대해서는 하네스 수준에서 차단 룰(Safety Gate)을 가동하여 메모리 오염을 방지해야 한다.
