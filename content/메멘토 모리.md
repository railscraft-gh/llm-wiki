# 메멘토 모리

## 한 줄 정의
'죽음을 기억하라'는 라틴어 경구로, 시간과 생명의 유한함을 인식함으로써 삶의 긴장감(Stakes)을 높이고 외적 제약을 통해 본질적인 작업에 집중하게 만드는 생산성 및 에이전트 설계 철학이다.

## 핵심 요지
- **유한성의 인지**: 인간이나 AI 에이전트나 시간과 자원이 무한하다고 느낄 때 태만해지거나 무한 루프(Vibe Coding)에 빠지기 쉽다. 유한함을 실감할 때(Memento Mori) 비로소 집중의 깊이가 달라진다.
- **제약(Constraints)의 힘**: 훌륭한 도구나 아침 루틴보다 강력한 생산성 지렛대는 단단한 외적 제약과 스스로 감당해야 하는 책임(Stakes)이다. 괴테가 말했듯 "제약 속에서 비로소 장인의 솜씨가 드러난다".
- **우선순위의 자동 조율**: 시간의 유한성을 직시하면 본래 미미하고 불필요한 잡무들이 정리되고, 핵심 과업(새로운 칼럼 집필, 운동, 사교의 본질 등)에 몰입하는 시스템이 자연스럽게 구축된다.
- **AI 에이전트 시스템에의 투영**: 에이전트에 무한한 자원(토큰, 이터레이션)을 주는 대신, 컨텍스트 윈도우 한계나 예산 제약(Token/Time Budget)을 명시적으로 주입하는 것이 오히려 불필요한 환각과 방황을 막는 열쇠가 된다.

## 상세
메멘토 모리는 대개 머리로만 이해되지만, 삶의 중대한 변화(예: 자녀의 탄생, 노화의 실감, 스페인이나 네덜란드로의 이주 등)와 같은 강한 외적 이벤트는 이를 온몸으로 느끼게 만든다. 
작가는 아이의 탄생으로 쓸 수 있는 절대적인 시간은 줄어들었으나, 기회의 창이 언제 닫힐지 모른다는 긴장감 덕분에 30분의 자투리 시간에도 무섭게 몰입하여 오히려 더 많은 일을 완수하게 되었다.

### 생산성 관점에서의 해석
세네카는 "우리에게 주어진 수명이 짧은 것이 아니라, 우리가 너무 많은 시간을 낭비하는 것이다"라며 시간의 무게를 느끼지 못하는 태도를 지적했다. 
앱이나 도구, 새벽 기상 루틴 같은 세부 요소에 집착하기보다, **행동의 결과를 스스로 감당해야 하는 상황(Stakes)**을 만들어 집중을 극대화하는 것이 진정한 생산성의 비결이다.

### [[LLM]] 및 에이전트 설계로의 확장 (Constraint-Driven Agent)
에이전트 아키텍처에서도 동일한 원리가 적용된다. 에이전트가 끝없는 자가 수정 루프를 돌며 토큰을 낭비하는 현상(바이브 코딩)을 막기 위해서는, 프롬프트 레벨이나 시스템 런타임에 단단한 외적 제약을 부여해야 한다. 
예를 들어, 에이전트의 남은 수명(Remaining Steps)이나 허용 토큰 예산(Token Budget)을 상태(State)로 전달하여 스스로 최단 경로를 선택하도록 유도하는 디자인 패턴은 메멘토 모리 철학의 기술적 구현체이다.

## 예시

### 1. 생산성 혁신 시나리오 (아기띠와 트레드밀 데스크)
작가는 아들을 아기띠로 메고 천천히 걷다가 아이가 잠들면 트레드밀 데스크에서 가장 느린 속도로 걸으며 글을 썼다. 이 단단한 제약 하에 3월과 4월의 칼럼 대부분을 완성했다. 또한 하루 20~30분 남짓 상체 밀기/당기기/하체 동작 3가지만 수행하는 단축형 운동 루틴을 통해 더 꾸준히 몸을 관리할 수 있었다.

### 2. [[LLM]] 에이전트 제약 주입 프롬프트 예시 (Python & LangChain/Gemini)
에이전트가 매 단계마다 자신의 '생존 한계(유한성)'를 인지하도록 프롬프트에 남은 예산(Budget)과 단계(Steps)를 주입하고, 이를 기반으로 의사결정을 내리게 하는 가상의 제약 주입 에이전트 예시 코드이다.

```python
import os
from google import genai
from google.genai import types

def run_constrained_agent(task: str, max_steps: int = 5, token_budget: int = 10000):
    client = genai.Client()
    current_step = 1
    used_tokens = 0
    
    # 에이전트에게 유한한 생명(Memento Mori)과 제약을 인식시키는 프롬프트
    system_instruction = """
    당신은 '메멘토 모리' 원칙에 따라 작동하는 극도로 효율적인 에이전트입니다.
    당신에게 주어진 단계(Steps)와 토큰 예산(Token Budget)은 엄격히 제한되어 있습니다.
    자원이 소진되면 작업은 즉시 실패로 종료됩니다.
    
    행동 지침:
    1. 쓸데없는 중간 설명이나 방황을 절대 하지 마십시오.
    2. 매 단계마다 남은 자원을 확인하고, 가장 빠르고 확실한 지름길로 목표를 달성하십시오.
    3. 완벽주의에 빠져 무한 루프를 돌지 말고, 제한 시간 내에 타협 가능한 최선의 결과를 도출하십시오.
    """
    
    while current_step <= max_steps and used_tokens < token_budget:
        remaining_steps = max_steps - current_step + 1
        remaining_budget = token_budget - used_tokens
        
        # 현재 단계의 제약 정보를 컨텍스트에 직접 주입
        constraint_context = f"""
        [CURRENT CONSTRAINTS (MEMENTO MORI)]
        - 현재 단계: {current_step} / {max_steps} (남은 단계: {remaining_steps})
        - 남은 토큰 예산: {remaining_budget} tokens
        
        목표 작업: {task}
        이전 기록을 바탕으로 다음 행동을 취하거나, 최종 답변을 제출하십시오.
        """
        
        print(f"\\n--- Step {current_step} (Remaining: {remaining_steps} steps, Budget: {remaining_budget} tokens) ---")
        
        # 모델 호출 (Gemini 2.5 Flash / Gemini 1.5 Pro 등 활용 가능)
        response = client.models.generate_content(
            model='gemini-2.5-flash',
            contents=constraint_context,
            config=types.GenerateContentConfig(
                system_instruction=system_instruction,
                temperature=0.1
            )
        )
        
        # 사용된 토큰 계산 (가상으로 응답 길이를 기준으로 계산)
        prompt_tokens = len(constraint_context.split()) * 1.3
        response_tokens = len(response.text.split()) * 1.3
        used_tokens += int(prompt_tokens + response_tokens)
        
        print(f"Agent Action:\\n{response.text}")
        
        # 에이전트가 완료(Task Complete)를 선언했는지 확인
        if "TASK_COMPLETE" in response.text:
            print("\\n[성공] 에이전트가 제약 내에 작업을 완수했습니다.")
            break
            
        current_step += 1
    else:
        if used_tokens >= token_budget:
            print("\\n[실패] 토큰 예산 초과로 작업이 강제 종료되었습니다. (메멘토 모리)")
        else:
            print("\\n[실패] 최대 단계를 초과했습니다. (메멘토 모리)")
```
