# 프로덕트 디자이너 스킬 스택 (Product Designer Skill Stack)

## 한 줄 정의
프로덕트 디자이너 스킬 스택은 피그마 중심의 단순 UI/UX 실행(Execution) 역량을 넘어, 비즈니스, 데이터, AI 워크플로우, 시스템적 사고 및 엔지니어링 협업을 포괄하는 다차원적 전문성 모음이다.

## 핵심 요지
- **디자이너 역할의 패러다임 변화**: AI를 활용한 단순 UI 생성 자동화와 전사적 디자인 시스템 도입으로 인해, 디자이너는 픽셀 조각가가 아닌 비즈니스 지표를 함께 책임지는 '프로덕트 전문가(Product Person)'로 진화해야 한다.
- **7가지 핵심 스킬 스택**: 
  1. **UX 리서치**: 유도 질문을 배제한 사용자 관찰 및 날것의 데이터로부터 핵심 실행 항목(Action Item) 도출.
  2. **프로덕트 씽킹 (Product Thinking)**: 기능 구현 이전에 문제의 본질(Why)과 비즈니스 하류 효과를 탐색하는 능력.
  3. **디자인 시스템 (Design Systems)**: 일회성 컴포넌트 생성을 지양하고 디자이너와 엔지니어 간 공용어로 소통하는 시스템적 사고.
  4. **데이터 분석 (Analytics)**: 퍼널 분석과 대시보드를 기반으로 디자인 의사결정의 근거를 마련하는 정량적 분석력.
  5. **AI 워크플로우 (AI Workflows)**: 초안(Draft) 고속화 도구로서 AI를 활용하고, AI의 불확실성과 오류 대응을 설계하는 제품 경험 역량.
  6. **비즈니스 이해도 (Business Understanding)**: 기업의 북극성 지표와 수익 구조에 맞추어 디자인의 가치와 리스크를 비즈니스 언어로 환산하는 조율력.
  7. **기초 프론트엔드 지식**: 개발 가능(Buildable)한 설계를 위해 HTML, CSS 및 컴포넌트 프레임워크의 동작 방식을 파악하는 엔지니어링 프로토콜 이해력.

## 상세
### 스킬 영역별 상세 실무 요구사항
- **UX 리서치**: 리서치를 예산 유무에 따른 옵션으로 취급하는 것은 본말전도다. 타겟 사용자 단 2명을 찾아 과제를 주고 45분 동안 관찰하는 것만으로도 무의미한 가정을 파괴할 수 있다 [raw/The Product Designer Skill Stack for 2026. 8 Skills That Matter More Than UI Design.md](file:///Users/railscraft/Obsidian/raw/The%20Product%20Designer%20Skill%20Stack%20for%202026.%208%20Skills%20That%20Matter%20More%20Than%20UI%20Design.md#L35-L36).
- **데이터 분석**: 데이터는 공감을 배제하는 숫자가 아니라 사용자의 불편을 보여주는 비명이다. 예컨대 퍼널 3단계에서 60%의 사용자가 이탈하는 병목 구간을 발견하여 문제를 파악하는 식이다 [raw/The Product Designer Skill Stack for 2026. 8 Skills That Matter More Than UI Design.md](file:///Users/railscraft/Obsidian/raw/The%20Product%20Designer%20Skill%20Stack%20for%202026.%208%20Skills%20That%20Matter%20More%20Than%20UI%20Design.md#L67). "CTA 버튼 위치 변경으로 전환율 12% 향상"과 같이 디자인 가치를 숫자로 소통한다 [raw/The Product Designer Skill Stack for 2026. 8 Skills That Matter More Than UI Design.md](file:///Users/railscraft/Obsidian/raw/The%20Product%20Designer%20Skill%20Stack%20for%202026.%208%20Skills%20That%20Matter%20More%20Than%20UI%20Design.md#L71).
- **AI 경험 설계**: 단순히 AI를 작업 툴로 쓰는 단계를 넘어, 제품 내 AI 도입 시 시스템 환각(Hallucination)에 대한 예외 처리와 사용자가 때때로 불안정한 에이전트 시스템에 신뢰를 갖도록 돕는 UX(Designing for Uncertainty) 설계가 요구된다.
- **기초 개발 지식**: CSS 변수(Variables), 컨테이너 쿼리(Container Queries) 등의 기술 제약조건을 인지하여 개발자에게 비현실적인 레이아웃을 넘기는 핸드오프 부채를 방지한다.

## 예시
- **프로덕트 씽킹 적용**: 신규 화면 설계 요청 시, 바로 와이어프레임을 그리지 않고 "이 화면이 해결하려는 핵심 비즈니스 문제는 무엇이며 3개월 뒤의 성공 모습(Success)을 어떻게 정의할 것인가?"를 명문화한 후 작업을 시작한다.

## 충돌
- **전업 전문가의 깊이 vs. 디자이너의 풀스택화**: 데이터 분석가, 프론트엔드 개발자, UX 리서처 등 각 분야 전문 인력의 고유 지식 영역과 프로덕트 디자이너의 제너럴리스트 성향은 상충할 수 있다. 디자이너가 각 역할을 대체하려 해서는 안 되며, 협업을 위한 '적정 수준(Just enough)'의 지식을 지도로 삼고 자신의 설계에 녹여내는 선에서 타협을 취해야 한다.
