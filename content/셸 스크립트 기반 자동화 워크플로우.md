# 셸 스크립트 기반 자동화 워크플로우

## 한 줄 정의
반복적인 명령줄 작업을 셸 스크립트 및 셸 함수로 구조화하여 오작동을 줄이고 개발 생산성을 높이는 CLI 터미널 내 경량 자동화 워크플로우.

## 핵심 요지
* **경량 유틸리티 지향**: 500줄 이상의 거대한 스크립트보다 매일 반복 입력하는 단순 작업을 10~30줄 크기의 스크립트나 함수로 쪼개 관리하는 것이 실무에서 더욱 가치 있다.
* **셸 함수와 스크립트의 분리**: 작업 디렉터리를 변경하는 등 현재 터미널 세션의 상태에 직접적인 영향을 주어야 하는 유틸리티는 셸 스크립트가 아닌 셸 함수(Shell Function) 형태로 배포 및 등록되어야 한다.
* **오류 가드레일**: 셸 스크립트 상단에 `set -euo pipefail` 옵션을 정의하여 에러 발생 시 즉각 중단하고 예기치 않은 시스템 파괴를 방지한다.
* **체크섬 기반 파일 비교**: 파일명을 단순 비교하는 것보다 `md5sum` 등의 암호화 체크섬 기반 해시값을 비교함으로써 파일 중복 제거 등의 정밀한 정리가 가능하다.

## 상세
### 1. 환경 제어를 위한 셸 함수 패턴
터미널의 작업 디렉터리를 직접 변경하는 명령어(`cd`)는 독립형 셸 스크립트 안에서 수행할 경우 스크립트 실행이 완료되는 즉시 원래 위치로 복귀한다. 스크립트는 자체 자식 프로세스(Subshell)를 생성하기 때문이다. 따라서 디렉터리를 생성하고 내부로 진입하는 작업 등은 반드시 사용자의 `~/.bashrc` 또는 `~/.zshrc`에 셸 함수로 추가하여 실행 환경의 컨텍스트를 제어해야 한다.

### 2. 가로채기 방지 및 타임스탬프 스냅샷
설정 파일을 편집하기 전 스크립트를 통해 파일의 백업 스냅샷을 남길 때, 단순히 `.bak` 접미사만을 사용하면 이전 백업을 덮어쓸 위험이 존재한다. `date +%Y%m%d-%H%M%S` 와 같은 세밀한 초 단위 타임스탬프를 조합하여 복구 지점을 고유하게 확보함으로써 수동 백업 실수를 사전에 차단한다.

### 3. 멀티 로그 추적기
마이크로서비스나 다중 백그라운드 프로세스가 실행되는 환경에서는 개별 터미널 창을 띄워 각각 로그를 수집하는 대신, 단일 스크립트를 통해 다중 백그라운드 작업(`&`)의 출력 스트림을 실시간 감시(Watch)하며, 스트림별로 다른 ANSI 색상 코드(e.g., `\033[31m`)를 매핑하여 터미널 하나에서 동시 디버깅할 수 있는 환경을 구축한다.

## 예시
### 디렉터리 생성 후 즉시 진입하는 `mkcd` 함수
```bash
# ~/.bashrc 또는 ~/.zshrc 에 등록하여 사용
mkcd() {
    if [ -z "$1" ]; then
        echo "사용법: mkcd <directory_path>"
        return 1
    fi
    mkdir -p "$1" && cd "$1"
}
```

### 타임스탬프 기반 파일 백업 스크립트 (`bak`)
```bash
#!/usr/bin/env bash
set -euo pipefail

if $; then
    echo "사용법: bak <file> [file ...]" >&2
    exit 1
fi

TIMESTAMP=$(date +%Y%m%d-%H%M%S)

for file in "$@"; do
    if ! -e "$file"; then
        echo "bak: '$file' 파일을 찾을 수 없습니다" >&2
        continue
    fi
    backup="${file}.${TIMESTAMP}.bak"
    cp -a -- "$file" "$backup"
    echo "백업 파일 생성됨: $backup"
done
```

## 충돌
* **부모 셸 컨텍스트의 영향성**: 작업 디렉터리를 변경하는 스크립트 실행 시 현재 터미널 세션의 경로가 이동되지 않는 현상이 발생한다. 이는 하위 프로세스 셸 실행 규칙에 기인하며, `cd`가 포함된 자동화 워크플로우를 독립 스크립트로 작성했을 때 발생하므로 셸 함수를 쓰도록 권장한다.
